## N1 — non-blocking
Claim: The reversal made Route overridable while leaving this document's own Hard constraints as the stated grounds for the fresh default, so the document now both forbids and licenses executing a cycle in the conversation that produced it, with no precedence stated between them.
Location: `skills/spec-review-cycle.md:139-145`, against `:29-32` and `:61-62`
Evidence: Verified by running. `git show a7a915c^:skills/spec-review-cycle.md` shows the pre-reversal paragraph closing "Both hold for every directive of this class, so stating them per cycle adds no information" — the Hard-constraints citation and the class fixity said the same thing, and no override was admitted. The revision keeps the citation at `:139-141` ("**route fresh** — one conversation per cycle, and execution starts a session that holds none of it (Hard constraints above, and `skills/directive-dispatch.md` §1 Route)") and adds at `:143-145` "These are defaults, not fixities: a cycle that needs existing context or a different model states that instead, and the stated field governs." `:29-32` is "**One conversation per cycle.** Each cycle starts a fresh chat … Never carry forward chat history," under a heading reading `## Hard constraints`; `:61-62` is "The cycle chat is done. Do not continue into execution in the same conversation." `skills/directive-dispatch.md:43-44` defines the alternative as "**Existing context** — only when the work depends on state the running session holds," and at directive-emission time in this class the session holding that state is the cycle chat. The seam is local to this document: `git grep -n "Hard constraints" -- skills/directive-dispatch.md LEXICON.md` returns nothing, so neither mirror grounds the default in a constraint it then licenses overriding.
Consequence: An author who wants to keep triage state writes `Route: existing context`, executes in the cycle chat on the strength of "the stated field governs", and carries chat history into execution — the failure the Hard constraints exist to prevent. Nothing in the document says the Hard constraint wins; the reader has to infer it from a section title. Likelihood is low, because "Hard constraints" and step 5's unqualified prohibition both point the other way, but the ambiguity is new — it did not exist under the prior text, which admitted no override at all — and it sits in a canonical process document at the point of agreement.
Fix: One clause after "the stated field governs", saying what the override reaches: route selects the **execution** session (`LEXICON.md`, the three layers), so `existing context` names an already-running execution session and never releases the Hard constraints or step 5, which forbid execution in the cycle chat whatever route is stated. This keeps route overridable, as `DEC-000150` requires — stating a field is not the same as being free to choose its value without limit — and removes the reading in which a stated field overrides a hard constraint.
