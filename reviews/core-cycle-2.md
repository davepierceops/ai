## CORE-9 — blocking
Claim: CORE-1's rescope narrowed rule 14 but did not close it — the rule still
forbids the review-artifact filename that `skills/spec-review-cycle.md`
mandates, including the two names this cycle's own directive orders.
Location: `docs/global-context/core.md:33`
Evidence: Verified by running. Rule 14's primary clause is unrestricted — "A
filename you generate is `<descriptor>-<timestamp>`" — and its single stated
exception is "A canonical document keeps a stable descriptive name." A review
artifact is neither: it is generated by the agent that produces it, and it is
not a canonical document. `grep -n 'reviews/<stem>-cycle-<n>'
skills/spec-review-cycle.md` returns line 229, which fixes the name to
`reviews/<stem>-cycle-<n>.md` and states the convention is "mechanical on
purpose" because `last-reviewed:` points at these paths. `ls reviews | wc -l`
returns 72 and `ls reviews | grep -cE '[0-9]{8}T[0-9]{6}'` returns 0 — every
existing artifact follows the skill and none satisfies rule 14. The
enumeration meant to bound the rule does not rescue it: `grep -rn "session
artifact" --include="*.md" .` returns only rule 14 itself and the cycle-1
review and directive that produced its wording, and `grep -c "session
artifact" LEXICON.md` returns 0 — the term appears in no definition anywhere
in the corpus, and LEXICON's own decision-session entry (`LEXICON.md:47-50`)
enumerates "directives, session records, tracker updates" without it. The two
artifacts this directive orders, `reviews/core-cycle-2.md` and
`reviews/decision-layer-cycle-2.md`, are the live instance.
Consequence: An agent writing a review artifact holds two rules that give
different names, and the revision supplied the tiebreak that resolves it the
wrong way. `core.md:10` now states that "a rule in a layer that conflicts with
a rule here does not waive it," and `inventory.md:148` places skills at order
3 — loaded after core, so a layer in exactly that sense. Applied, core rule 14
outranks the skill, the agent emits
`reviews/core-cycle-<timestamp>.md`, and the derivable path that a reader and
`bin/flip-agreed`'s pointer both depend on stops matching the document it
reviews. This is CORE-1's failure mode surviving at reduced blast radius: 215
of 217 files before, one artifact class now — but that class is the most
frequently generated in the repository, and the new precedence clause makes
the silent wrong resolution the correct one.
Fix: Extend rule 14's exception to cover it — a name a governing convention
fixes keeps that name — or state that the em-dash enumeration is exhaustive so
an unlisted class falls outside the rule. Either closes it; the current text
does neither, and "session artifacts" cannot carry the scope while it is
defined nowhere the reader can reach.

## CORE-10 — non-blocking
Claim: Rule 6's new definitional clause contradicts the sentence that follows
it, and the contradiction opens an escape from rules 5 and 10.
Location: `docs/global-context/core.md:22`
Evidence: Verified by running that the clause is new — `git diff 5aa02c5
04bfeae -- docs/global-context/core.md | grep -c 'An assertion about state'`
returns 1, so the definition arrived with this revision while the sentence it
collides with is unchanged. Inferred by reading the two together: the first
clause defines a claim by its content ("An assertion about state, results,
verification, or completeness is a claim"), the third asserts a form test ("A
claim without a class is not a claim"). Substituted, the second reads: an
unclassed assertion about state is not an assertion about state. At cycle 1
the form test stood alone as a stipulation and had nothing to contradict;
CORE-7's fix supplied the content definition without reconciling it.
Consequence: Rules 5 and 10 both key on the word — "Claims require evidence"
and "Findings are claims." An agent that takes the form test literally
concludes that an assertion it left unlabelled is not a claim, and therefore
that rule 5's evidence requirement does not reach it. The sentence intended to
enforce labelling becomes the sentence that excuses its absence, in the one
file every session loads.
Fix: Cut the form test, or restate it so it does not redefine the term the
sentence before it just defined — an unclassed claim carries no weight, rather
than is not a claim.
