## B1 — blocking
Claim: The route has no `specs/` exclusion, so a co-authored PRD or TRD reaches `agreed` without the Spec Reviewer gate.
Location: `policies/document-metadata-policy.md:284-295` (`### Eligible when all four hold`)
Evidence: Verified by reading all four conditions against the expedited path's condition 4 (`:205-207`: "The document is not under `specs/`. Spec agreement is gated by the Spec Reviewer Agent … this path does not reach that gate and does not override it") and against `DEC-000010`, which scopes the route to "a co-authored methodology/governance document". Condition 1's discriminator is prose-vs-program ("**Prose, not a program.** … a script or executable is out"), not methodology-vs-spec, so a PRD passes it. Conditions 2–4 are satisfiable for a co-authored non-gate PRD: a PRD states requirements, not "a gate, hard stop, or enforcement rule over how work is reviewed, agreed, or released". `roles/spec-reviewer-agent.md:21-30` makes gate review a hard gate on "initial authorship of any canonical document" including PRD and TRD.
Consequence: Dave and an agent co-author a PRD in the artifact pane, run a sweep, and flip it to `agreed` with a line in the expedited log. `bin/flip-agreed` permits it — `specs/**` is in the frontmatter in-scope set (verified by running: `scope.load_globs` returns the nine globs including `specs/**`), and the tool checks only pointer format, artifact existence, SHA resolution, log-entry match, and frontmatter-only. The one gate the repo has always treated as non-negotiable is bypassed by a route whose text never mentions it.
Fix: Add the exclusion as a fifth condition, in the expedited path's own words — the document is not under `specs/`; spec agreement is gated by the Spec Reviewer Agent and this route neither reaches nor overrides that gate. If Dave instead intends the route to cover co-authored specs, that is a change to the Spec Reviewer's reach and belongs in `roles/spec-reviewer-agent.md` and a decision-log entry, not in silence here.

## B2 — blocking
Claim: Condition 4 rests on a "consistency sweep" that no document in the repo defines.
Location: `policies/document-metadata-policy.md:294-295`
Evidence: Verified by running `grep -rn "consistency sweep" --include=*.md .` — two hits, both restating the requirement rather than defining it: this line and `decisions/log.md:11` (`DEC-000010`). `context-sets/collab-workflow.md`, the portable source of truth for artifact-pane co-authoring, does not name it. The closest defined artifact is the Spec Reviewer's continuity scan (`roles/spec-reviewer-agent.md:68-106`), which has three named depths and a required output shape — and this route deliberately does not invoke it.
Consequence: The one structural requirement in an otherwise judgment-based route cannot be evaluated. An agent asked whether condition 4 is met has to guess the scope (this document? the documents it cross-references? the whole methodology?), who runs it (the co-authoring agent, which is the same instance that wrote the text), and what evidence it leaves. Nothing in the sequence records that a sweep happened, so a later reader cannot tell a swept agreement from an unswept one — and the sweep is exactly what this route substitutes for the reviewer.
Fix: Define it where it is required: minimally, what is swept (the document against the documents it references and that reference it), by whom, and that "at least one" means the last sweep post-dates the final edit. If the intended meaning is a Depth-1/2 continuity scan under `roles/spec-reviewer-agent.md`, say so and cite it; if it is deliberately lighter, say what it drops.

## B3 — blocking
Claim: The route is written entirely in the singular and never states whether one doc-only agreement may carry more than one document — the multi-file freedom `DEC-000030` explicitly retains.
Location: `policies/document-metadata-policy.md:277-282` (intro) and `:297-302` (`### Sequence`)
Evidence: Verified by reading. `DEC-000030` retains the override of "the expedited path's ≤10-line body cap **and single-in-scope-file rule**" for co-authored documents; the section implements the size half explicitly ("of **any size**, new or revised") and the single-file half only by implication, in a contrast clause ("where the expedited path is capped at a ten-line single-file revision"). Every operative sentence is singular: "a co-authored document", "the log entry naming that SHA", "a frontmatter-only flip". `context-sets/collab-workflow.md:29-31` describes multi-document co-authoring sessions as routine, so the case is not hypothetical.
Consequence: An agent finishing a two-document co-authoring session has no stated rule. Reading the route as inheriting the expedited path's condition 1 (it "records like the expedited path") forces two separate cycles for work Dave signed off once; reading the contrast clause as lifting it leaves recording undefined — one log line or two, and which SHA the second document's `last-reviewed` cites when both landed in one content commit. `bin/flip-agreed` refuses unrelated staged changes and touches exactly one path per commit (verified by reading `check_preconditions` and the post-commit `touched == [relpath]` assertion), so whichever reading is intended, the flip is per-document and the text should say it.
Fix: State it: whether a doc-only content commit may touch more than one in-scope document, and if so that the log takes one entry per document and each document's `last-reviewed` cites the same content SHA, with a separate frontmatter-only flip per document.
Related: B2

## N1 — non-blocking
Claim: The cross-reference to `### The record` resolves to a rule scoped by its own terms to expedited agreements, and the log it points at is scoped the same way.
Location: `policies/document-metadata-policy.md:279-281` → `:230-236`; `reviews/expedited-log.md:1-6`
Evidence: Verified by reading. The record's opening sentence is "Each **expedited** agreement appends one line to `reviews/expedited-log.md` …", and the log's header reads "One line per **expedited** agreement, per the 'Expedited return to `agreed`' section of `policies/document-metadata-policy.md`". The log's sole entry is a doc-only agreement, not an expedited one (`reviews/expedited-log.md:28`, `policies/decision-log-policy.md` under `DEC-000020`) — so the mismatch already exists in the record. The log's entry format `- <date> — <path> @ <sha> — <what changed, one clause>` also assumes a revision, where this route explicitly admits new documents; the existing entry works around it in prose ("founding decision-log policy").
Consequence: A reader following the pointer lands on a rule that by its terms governs a different route, and a checker or agent reading the log header concludes doc-only entries do not belong there. Nothing breaks mechanically — `bin/aimeta/expedited.py` matches on SHA, not on provenance — but the record's own description of itself is wrong about half its content.

## N4 — non-blocking
Claim: The route presumes a frontmatter-carrying document but says only "in any format", and out-of-scope documents cannot complete its sequence.
Location: `policies/document-metadata-policy.md:285-287` (condition 1), `:297-302` (`### Sequence`)
Evidence: Verified by reading condition 1 and by running `bin/aimeta/scope.load_globs`, which returns nine globs; `decisions/log.md` matches none (verified by running `scope.matches` → `False`), and `bin/flip-agreed` exits `EXIT_POLICY` with "is outside the frontmatter in-scope set" before doing anything else (`bin/flip-agreed:142-145`). The failure is fail-closed (a tool error, not a false agreement), which is why this is non-blocking.
Fix: One clause in the intro or condition 1: the route applies to documents in the frontmatter in-scope set, since `agreed` is a frontmatter state and documents outside that set have no lifecycle status to reach.

## N5 — non-blocking
Claim: The justifying sentence overstates what the route preserves, and the section carries no counterpart to the expedited path's statement of what enforcement cannot see.
Location: `policies/document-metadata-policy.md:277-279`
Evidence: Verified by reading. The text asserts "with no separate reviewer — the co-authoring *is* the read a reviewer would perform." `DEC-000030`'s Context states the opposite emphasis: "The doc-only cycle **trades away independent review**, and the one class where independence is load-bearing is the set of documents that define the routes to `agreed`." The expedited path devotes a paragraph to the same candour (`:219-223`: "Enforcement checks none of this and cannot … conditions 3 and 5 are judgments, and they are what make the path a review at all"); the doc-only section has no equivalent, and its conditions are three judgments and one undefined procedure (B2).
Consequence: The claim is true about the *reading* and false about the *independence*, and as written it reads as the latter. A future argument for widening the route — including over the gate-doc class condition 3 excludes — can quote this sentence as the policy's own position that co-authoring equals review.
Fix: Name the trade in the same sentence, in `DEC-000030`'s terms: the co-authoring supplies the read, not an independent reader, which is why the gate-doc class is excluded. A one-line counterpart to the expedited path's enforcement paragraph would close it.
