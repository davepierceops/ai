# Retro — fiducial — 2026-08-21

## Context

Dave asked for a universal context file: the rules every LLM agent should get regardless of domain, extracted from the engineering methodology (`ai`) and the writing methodology (`writing`). The session swept both repos, built a 70-row inventory, triaged it row by row, drafted `core.md` and `decision-layer.md`, and along the way decided the audience split, bundling by frontmatter, a single public repo, and the rename to `fiducial`. Drafts landed at `a97c931` (PR #75).

## Evidence

1. The project-knowledge bundle was 43 commits stale (2026-08-09 vs HEAD 2026-08-18). Track A/B had been retired and the entire `engagements/` layer postdated it. I read from a fresh clone, not the bundle.
2. Before reading the current `directive-dispatch.md`, I re-presented the retired "one-line kickoff" rule (B11) and Track B's sync-block rule (D5) from memory. Dave corrected both; both were discarded.
3. `engagements/working-with-dave.md` (2026-08-11) already opened with "load this file in every session" and was ~80% domain-neutral — a prototype of the global file that existed before the request.
4. ~20 rules appeared independently in both repos with near-identical wording (state computed not maintained; only flag what you can demonstrate; no random filenames; proposes-doesn't-decide).
5. Partway through the audience pass Dave introduced the decision/execution session distinction; it reclassified roughly half the rows and the file split into two layers.
6. Dave rejected my proposal to generalize B6 ("assess state on invocation") as "a hundred percent role-specific." Same disposition later for B9/G3, F6, G4, G7 — all authoring or role machinery, not agent behaviour.
7. On G6 I proposed demotion because the miss seemed rare; Dave: "it has not been my experience. I wrote this rule because it was a common miss." Kept at High.
8. Dave flagged `load-bearing` as overused ("used up your quota about a month ago"). Two instances in the drafts; both removed.
9. On rule 5 (pre-stage) Dave asked whether either of two trailing phrases was necessary. Neither was; the same cut then applied to ~14 other rules across both files. Core went 40 → 27 lines.
10. The manifest proposal was superseded within the same session by Dave's inverted-index idea: membership in each file's `audience:` frontmatter, which already exists.
11. I wrote "Running it" for the retro and did not run it. Dave: "you don't seem to be doing anything though."

## Interpretation

- (1, 2) A stale bundle plus memory-first drafting produced exactly the defect core rule 8 names. The fix was structural (read the clone), and the rule now exists in core — but the bundle staleness itself was invisible until checked. Bundler output should stamp its age prominently.
- (3, 4) The global rules were already written, twice, in different words. Convergent independent statement across repos was the strongest signal of globality and would have been a faster first-pass triage heuristic than my judgment per row.
- (5) The most consequential structural decision came from Dave mid-process, not from the inventory. Asking "who receives this?" before "is this global?" would have been the right order.
- (6) My systematic bias this session: classifying authoring principles and role machinery as agent rules. Five rows, same correction each time. The test Dave applied — "is this an instruction to the agent, or a rule for the person writing instructions?" — belongs in whatever criteria govern instruction-writing.
- (7) I demoted on assumed frequency without evidence; Dave had the evidence. Priority proposals should state their basis or not be made.
- (8, 9) The cut that removed "never X" restatements and trailing rationale was mechanical once named and shrank the file by a third with no loss. This is `machinery-criteria.md`'s rule applied; I had not applied it on first draft.
- (11) Announcing an action in the same turn as completing a previous one, then not doing it, is a failure of decision-layer rule 7 (deliver, don't plan) in its smallest form.

## Durable insights

- Convergent statement across independent repos is a triage heuristic for globality.
- "Agent instruction or authoring principle?" is a test to apply before proposing any rule for an agent-facing file.
- Priority proposals state their basis. "Rare" is a claim.
- First-draft machinery prose gets the restatement/rationale cut before it is shown, not after.

## Candidate methodology changes

- `bin/bundle` (or its successor): print commits-behind-HEAD and generation age at the top of every bundle, so staleness is visible at load.
- Add the authoring-vs-agent test to the instruction-writing criteria (`machinery-criteria.md` successor in `fiducial`).
- Decision layer rule 7 could gain: a stated action is performed in the same turn it is stated.
