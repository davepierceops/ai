# Retro — ai — 2026-08-11

## Context

A fable session opened on the felt friction of the methodology, identified two
structural sources (GitHub-MCP-in-the-dispatch-path; per-edit spec gating),
designed replacements (paste-block dispatch with executor-side landing; open
spec deltas with reconciliation), executed both via a first-of-its-kind
overnight autonomous directive, triaged and corrected the result the next
morning via a second autonomous run, promoted the resulting decisions, flipped
six documents to agreed, and closed the Trivium release layer.

2. Both friction diagnoses came from Dave's lived experience, not analysis:
   "waiting forever" on MCP writes; "it's too fucking expensive" to gate every

5. The nineties "merge hell" trigger was raised by Dave as a feeling, initially

6. The overnight run (33m, Opus) executed 14-document changes, ran 3 self-review

## Interpretation

- The two frictions shared one root (2, 3): work routed through the party for
  whom it was expensive. The durable design question that emerged — "what does
  this cost Dave in the loop?" — is now encoded in the operating habits.
- Dave's interruptions are load-bearing review (4, 5, 7, 10). The
  highest-value corrections in this session all arrived as refusals to keep
  reading. A response's first paragraph carries disproportionate weight; burying
  the point costs the correction.
- The autonomous-run pattern works (6, 9, 13) under three conditions that were
  all present: structural containment (branch, no flips), a decision log
  making judgment reviewable, and a morning triage that actually reversed
  something — proving the review is real, not ceremony.
- Self-review caught real regressions (9) but the independent catch rate is
  unknowable from inside; the pattern's safety still rests on the human diff
  review, as designed.
- Evidence-over-plausibility failures recur in chat even while the methodology
  enforces them in executors (8, 12): completeness claims from memory, scope
  claims without frontmatter checks. The corrective that worked both times was
  the same one the methodology prescribes — sweep, don't recall.
- Dave's exploration mode (10) is distinct from both fable mode and
  directive-production mode: probing what's possible with no intent to change
  anything. Claude misread it twice as an input-gathering phase for methodology
  work. The cost of the misread was Dave's attention spent correcting framing.

## Durable insights

- **Transport/record split for any artifact crossing a session boundary:** ask
  which job needs durability and who holds the cheap write path; route
  accordingly. Generalizes beyond directives.
- **Autonomous overnight execution is now a proven pattern** for
  well-decided, well-bounded work: binding decisions stated up front, branch
  containment, decision log, self-review to clean, morning triage with real
  reversal authority. Two runs, zero structural violations.
- **The operator works from the shell; artifacts should anticipate dumb-tool
  extraction.** Observed, not yet methodology (10): content destined for
  another file, embedded in prose, defeats cat and forces awk or a dispatch.
- **Response ordering is a compliance surface:** conclusions first, reasoning
  after, because the reader stops reading at the first wrong turn (4, 11).
- **A directive defect can be resolved by an executor empirically** (13) when
  the resolution is verifiable-not-judged — dry-run both readings, take the
  one that passes, report which and why.

## Candidate methodology changes

- Encode the shell-first operator constraint if Dave elects to: artifacts
  containing promotable/movable content keep it extractable by dumb tools
  (contiguous, delimited, or sidecar-filed). Phrased as input only; Dave
  explicitly deferred this during the session.
- Name and document the autonomous-run pattern (binding decisions → branch →
  decision log → self-review cap → morning triage) as a skill, if it is to
  recur. Two successful instances exist as its evidence base.
- The exploration mode (10) may deserve the same explicit naming fable mode
  received, so sessions can be told "answer, don't extrapolate" once instead
  of per-question.
