# Retro — fiducial — 2026-08-22

## Context
One decision session ran Pass 1 of the fiducial assembly from a standing start to cycle 15: rubric written, writing repo merged with history, eleven files through review, seven retired or merged, the dispatch rule and vocabulary reset. Fifteen execution sessions were directed; every directive and review artifact is on main.

## Evidence
1. The session opened from a project bundle generated 2026-08-09. The first three directives were committed chat-side via MCP with a sync block, contradicting a rule landed 2026-08-09 that the bundle predated. Dave caught it; the executor for cycle 2 also caught a route violation when Dave pasted into the authoring session.
2. Dave stated the directive rule verbatim ("run the following in a fresh or reused session, model tier, one paste block, first instruction writes the file") after the assistant had twice cited repo text from early August as binding. The repo text was on main and did say what the assistant said; Dave's rule superseded it unrecorded until cycle 6b wrote it into Core.
3. Five reviewer findings in cycles 2, 7, 9 and 14 were defects in wording the assistant had dictated (CORE-9, CORE-10, L9, L10, the cycle-12 merge residue), not in executor work.
4. Executors departed from directive wording fourteen times in cycle 12 alone, each flagged with reason; every departure was correct on inspection.
5. One executor reported a prompt-injection attempt arriving inside a tool result and disregarded it.
6. The MCP GitHub connector timed out once (4 min) while Dave was doing something on his end; `gh` from the clone completed the same PR in seven seconds.
7. Dave asked three times for plainer wording ("I don't understand item one"); each time the plain version was two sentences.
8. Dave copied a paste block before streaming finished; the executor refused the truncated directive.
9. Dave stopped mid-session and resumed the next morning in the same chat.

## Interpretation
- (1, 2) A stale bundle is indistinguishable from a current one to the reader. The age-stamp candidate from the 08-21 retro is now evidenced twice.
- (2) Rules Dave holds that the repo does not are the most dangerous class: the assistant will cite the repo in good faith and be wrong. The fix is to write the rule the moment it is spoken, which cycle 6b did.
- (3) Dictated wording in directives needs the same read-before-emit discipline as any governed text. The assistant wrote "session artifacts" and "a claim without a class is not a claim" from its head; reviewers caught both.
- (4, 5) Executors are reliable judges of directive intent and of their own environment; directives can state intent and single homes and let the executor resolve the Fix-vs-disposition conflicts.
- (6) MCP contention is a session-level event, not a tool defect; the fallback should be pre-staged, not composed under failure.
- (7) Two-sentence explanations are the right default for anything with a name Dave has not used himself.
- (9) A session can survive a night; what it cannot survive is its own length. The baton exists for this.

## Durable insights
- Write a spoken rule into governed text in the same turn it is spoken.
- Reviewer re-gates over dictated wording catch the assistant's errors, not the executor's; budget for one extra re-gate per cycle that dictates wording.
- Split reviewer scope at ~600 lines; executors handle 10-file revisions but reviewers degrade past six.
- Keep a `gh` open-and-merge block pre-written for MCP outages.

## Candidate methodology changes
- `bin/bundle-methodology`: stamp source repo name and bundle age; fail or warn when the source SHA is older than N commits behind main.
- Decision-layer candidate: "A rule Dave states that governed text lacks is written into governed text before the next directive is issued."
- Rubric criterion for Pass 2: a directive that dictates wording cites the governed text it derives from or marks the wording as new.
