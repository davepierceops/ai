## Interpretation

- The dominant cost of the morning was rework from the CoS reconstructing governed rules from memory instead of reading canonical text first (3, 5, 6, 11). Each instance forced a correction and a round-trip with a wait state. This is the drift-defect the methodology exists to prevent, produced by the role meant to prevent it.
- Two command-block failure modes appeared (3): copy-button suppression (already documented) and interactive-paste parse-stall (new). Same root — multi-line/stateful content through a paste buffer. The base64 blob (4) was an over-correction: it bought paste-safety by sacrificing the verbatim inspectability that defines a command block.
- The wrong diagnosis (5 → 11) is the highest-value finding. A governed mechanism (the hook's auto-flip) was read as damage, and the misreading propagated into a directive constraint that contradicted the governing policy — the "no blanket constraint may contradict an explicit instruction" defect named in `directive-dispatch.md`. Reading the hook and policy before asserting what "clean" looks like would have prevented both the constraint and the earlier alarm.
- Genuine gaps, separated from error tax:
  - Tooling (8): no repo connector in chat forced the full Track-B directive apparatus for a one-line change. With a connector this is one dispatch. This is a missing-connector gap, not methodology weight.
  - Methodology (2, and the routing that led there): a trivial, additive, owner-arbitrated change to an *enforcement-rule* document has no fast lane — doc-only is excluded, so it routes through override + DEC entry + expedited-log line + committed directive + execution session + PR. The tier system (routine/consequential for code, doc-only for prose) has a hole for trivial-additive governance edits under owner arbitration.

## Durable insights

- Read the governing skill/policy/hook before emitting the artifact it governs — not after correction. "I remember the rule" is the trigger to read the canonical text, not to proceed on memory. This was the root cause of most of the session's rework.
- A command block delivered to a human must be verbatim, copyable, **and** parse-atomic on paste. Multi-line or stateful content (heredocs, multi-line quoted strings, appended file bodies) ships as a file the executor writes with its own filesystem — never through the human's paste buffer. An encoded blob (base64) is not an acceptable substitute: it defeats the inspectability that makes a block a command block.
- A directive must not restate a diagnosis as a constraint. "Forbid X" where X is in fact a governed mechanism produces a constraint that contradicts policy. State the intended end-state and let governed mechanics operate.
- An owner override of a trivial change is legitimate and cheap. In this session the override was one line; the expense was the machinery around it — most of which was error tax, not the override.

## Candidate methodology changes

Inputs to a future review cycle, not decisions. Per this skill, a retro-surfaced
revision enters through the normal cycle — it does not use the expedited or
doc-only doors, even when they would otherwise apply. Marked by kind, per Dave's
framing that error tax should not drive methodology changes.

1. **[genuine gap] Trivial-additive fast lane for owner-arbitrated governance edits.** A tier analogous to the routine class in `commit-and-change-control-policy.md`, for changes that are additive, owner-approved, and tool-verifiable-green, so they do not route through the full override/directive/PR machinery. Needs scoping: what qualifies, and how it interacts with the enforcement-rule exclusion that made doc-only unavailable here. This is the one candidate that is a methodology hole rather than a symptom of this session's errors.

2. **[error-tax fix] `skills/command-blocks.md` — generalize copyability to parse-safety.** Add interactive-paste parse-stall as a second known instance alongside the copy-button case; add the positive rule that multi-line/stateful content ships as an executor-written file, never paste-buffer content; explicitly exclude encoded blobs as a substitute (they defeat verbatim inspectability); add a matching conformance criterion. Timing: `command-blocks.md` is a Trivium draft not yet gated — this wants to land before the gate reviews it.

3. **[error-tax fix] `skills/directive-dispatch.md` — diagnosis-as-constraint check.** Extend the existing constraint-vs-instruction rule: a directive constraint must be checked not only against the file's explicit instructions but against the governing policies and hooks it does not own, so a mistaken diagnosis is not frozen into a forbidding constraint.

4. **[error-tax fix, possibly a standing preference] Read-before-emit for governed artifacts.** The CoS (and any agent) reads the governing canonical text before producing a governed artifact. Whether this belongs in a role document, base behavior, or as a standing preference is for triage. Interacts with AI-15: Dave repeated standing preferences this session (one question at a time; verbatim/canonical delivery; do not work from memory) that, being repeated across sessions, belong in a governed document rather than re-corrected in-session.
