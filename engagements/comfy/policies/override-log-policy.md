# Policy: Override Log

## The rule

Every ceremonial element of this engagement pack — the baseline-gate, the
Skeptic verdict, the change-package shape, any procedural step — is trivially
overridable by Dave. The complete override protocol is:

1. Dave states, unambiguously, that he is overriding. "I say override"
   suffices. No justification is required in the moment.
2. The agent logs it and proceeds. The agent does not argue, re-litigate, or
   require ceremony around the override itself.

## The log

Append-only, at `engagements/comfy/override-log.md`. One line per override:

    date | what was overridden | one-line context | session/PR reference

The log is reviewed at the engagement retro. The retro is a short
end-of-engagement review, run by Dave; scheduling it is the CoS's job. The
log's purpose is tuning: a rule overridden often is a rule mis-sized for the
work, and the log is the evidence for resizing it. Overrides are data about
ceremony fit, not exceptions to be ashamed of.

## Exclusions

`client-credentials-policy.md` is excluded from field override. Escalation
paths (stop-and-ask-Dave) cannot be overridden by an agent's own judgment —
only Dave can waive a stop, which is itself an override and gets logged.
